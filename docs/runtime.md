# Asynchronous runtime

Requires PostgreSQL, PHP extensions required by Composer plus `pdo_pgsql`, and `pcntl` for graceful worker signal handling. Install with `composer install`, configure DATABASE_URL privately, then run `php bin/console doctrine:migrations:migrate --no-interaction`.

Write an `OutboxEvent` in the same transaction as the business mutation. Its payload contains identifiers and version references only. `php bin/console statecan:outbox:dispatch --limit=100` locks pending rows with SKIP LOCKED, enqueues and marks published atomically on the **same default Doctrine connection**. Do not replace those transports with remote transports without replacing the atomic delivery protocol. The dispatcher is safe to run concurrently and restarts at unpublished rows.

`App\Message\OutboxMessage` carries eventId/type/aggregateId/payload/correlationId. The handler dispatches a Symfony event named exactly `type`; use `#[AsEventListener(event: 'receipt.requested')]` and an `OutboxMessage` argument to handle it. Work already executes on the matching queue: `receipt.*` → receipts, `git.*` → git_indexing, `notification.*` → notifications, `maintenance.*` and `lease.*` → maintenance, others → state_events. Unknown non-task events fail instead of silently disappearing. A task ledger event may legitimately have no projection listeners.

All five queues and the failed queue share `messenger_messages`. Auto-setup is disabled; migrations own the schema. Transport notification polling is disabled so deployments need no database trigger setup. Retries use 1s exponential backoff, 20% jitter, maximum five retries and a 60s delay ceiling. Inspect/retry failures with `php bin/console messenger:failed:show` and `messenger:failed:retry`.

Job middleware records attempts, errors, correlation IDs and status; completed event IDs are suppressed on redelivery. PostgreSQL session advisory locks serialize attempts across workers without holding transactions during external operations. Process termination releases the lock. Messenger redelivers unacknowledged jobs after 300 seconds; run with `--keepalive=30` for longer handlers. A crash after an external effect but before the completion marker can repeat that effect: receipt/Git/notification handlers must implement their own deterministic idempotence. This is at-least-once delivery, not an atomic transaction with external storage. Custom typed messages should implement `App\Runtime\JobMessage` with a stable ID for retry-safe job identity.

Operator-only GET `/api/v1/operations/jobs`, `/queues`, `/health` expose bounded operational data. Job rows include status, attempts, correlation_id and latency_seconds; queue rows include depth, in_flight and oldest_age_seconds. Queue depth includes delayed/in-flight messages. Worker process liveness is explicitly not probed; health checks database availability, pending outbox and dead letters. Existing form auth remains in place; ROLE_OPERATOR is required.
